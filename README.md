# 변경관리 업무대장 (개인용 GitHub Pages 버전)

변경 등록 → 영향 평가 → 완료 보고 → 출력문서 배포/수령 확인 → 후속 업무 모니터링을 위한 개인용 웹 업무대장입니다.

## 1. GitHub Pages로 게시하기

1. GitHub에서 새 저장소(repository)를 만듭니다. 예: `qms-change-manager`
2. 압축을 풀고 `index.html`, `style.css`, `app.js`, `README.md`를 저장소 최상위(root)에 업로드합니다.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Build and deployment**에서 `Deploy from a branch`를 선택합니다.
5. Branch는 `main`, 폴더는 `/ (root)`로 설정하고 저장합니다.
6. 잠시 후 `https://깃허브아이디.github.io/qms-change-manager/` 주소로 접속합니다.

## 2. 사용 방법

- **변경 등록:** 변경 제목, 유형, 요청자, 목표 완료일, 중요도, 변경 사유 및 전·후 내용을 등록합니다.
- **영향 평가:** 변경 건 상세 화면에서 평가 분야, 평가 결과, 근거를 여러 항목으로 등록하고 종합 결론 및 평가 완료 여부를 저장합니다.
- **완료 보고서:** 실행 완료일, 담당자, 실행 결과, 검증 결과, 교육·문서개정 등 후속조치, 작성자 및 보고일을 입력합니다.
- **문서 배포:** 배포할 문서명/문서번호, 배포 대상, 배포일, 수령 요청일, 비고를 직접 입력합니다.
- **수령 확인:** 문서를 수령하면 미수령 목록에서 빠지고 수령 완료 이력으로 이동합니다. 수령일도 기록됩니다. 잘못 체크한 경우 ‘미수령으로 되돌리기’를 사용할 수 있습니다.
- **후속 업무:** 확인할 업무와 예정일을 등록하고 체크박스로 완료 여부를 관리합니다.
- **확인 필요 업무:** 기한 초과, 미수령 문서, 미완료 후속 업무를 모아 보여줍니다.
- **백업:** 상단의 ‘백업 내보내기’로 JSON 백업을 정기적으로 저장합니다. CSV는 변경관리대장 표 형식으로 내려받을 수 있습니다.

## 3. 데이터 저장 및 주의사항

- 이 버전은 별도 서버나 계정 없이 작동하도록 **현재 브라우저의 localStorage**에 데이터를 저장합니다.
- 같은 브라우저·같은 기기에서는 다시 접속해도 데이터가 남지만, 브라우저 데이터 삭제, 시크릿 모드, 기기 변경, 브라우저 변경 시 데이터가 사라질 수 있습니다.
- GitHub 저장소에 기록이 저장되는 것은 아닙니다. GitHub Pages는 화면 파일만 게시합니다.
- 정기적으로 JSON 백업 파일을 별도 위치에 보관하세요. 백업 파일에도 업무 정보가 포함되므로 안전한 위치에 보관해야 합니다.
- 개인 업무 추적용 도구이며, 회사의 승인된 QMS 기록 시스템이나 공식 문서관리 절차를 대체하지 않습니다. 공식 기록으로 사용하기 전에는 회사 절차 및 기록관리 요구사항에 맞는 검토가 필요합니다.

## 4. 브라우저 데이터 관련

이 앱은 브라우저 저장소를 사용합니다. 공용 PC에서 사용하지 말고, 브라우저 초기화/기기 교체 전 반드시 백업하세요. 개인 관리 목적이라도 제품·고객·임직원 관련 민감정보나 비밀번호 등은 입력하지 않는 것을 권장합니다.
